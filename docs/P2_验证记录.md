```
src/
├─ WolfpackModKit/                 框架本体（23.5 KB）
│   ├─ ModManifest.cs              清单模型 + IMod/ModBase + ModContext（日志/配置/Harmony/事件）
│   ├─ ModLoader.cs                发现 → 依赖排序 → 加载 → 隔离 → 逐帧 Tick

└─ samples/SampleHud/              参考 Mod（5.5 KB）
    ├─ SamplePlugin.cs             manifest→加载→Update→场景事件→贴图 全链路示例
    ├─ manifest.json
    └─ icon.png                    测试用 64×64 PNG
```

运行期目录约定：

```
Wolfpack/
├─ BepInEx/plugins/WolfpackModKit/WolfpackModKit.dll   ← 框架本体（BepInEx 插件）
└─ Mods/                                               ← 框架自有目录
    ├─ modkit.disabled                                  （可选：一行一个 ModId，用于禁用）
    ├─ modkit.quarantined.log                           （加载/运行失败记录）
    └─ SampleHud/{manifest.json, SampleHud.dll, icon.png, config/}
```

`manifest.json` 字段：`id / name / version / author / entry / assembly / gameVersion / dependsOn / network / loadOrder`。
`network` 取 `client-only | host-required | all-clients`，为后续公开房间策略预留。

## 3. 关键技术发现：ClassInjector 在本作不可用

**现象**：使用标准写法注入 `ModRunner : MonoBehaviour`（`RegisterTypeInIl2Cpp` + `new GameObject().AddComponent<>()`）后，游戏在场景切换（Boot → Setup）瞬间崩溃，无 Unity 异常、无崩溃转储。

**根因**（Windows 事件日志给出托管异常）：

```
Faulting module: KERNELBASE.dll   Exception code: 0xe0434352
System.InvalidOperationException: Handle is not initialized.
   at System.Runtime.InteropServices.GCHandle.FromIntPtr(IntPtr value)
   at Il2CppInterop.Runtime.Injection.ClassInjector.Finalize(IntPtr ptr)
   at Il2CppInterop.Runtime.Injection.ClassInjector.StaticVoidIntPtrInvoker(...)
```

即 **Il2CppInterop 为注入类型生成的终结器**：当 Unity 在场景切换时销毁该组件，终结器拿到未初始化的 GCHandle 直接抛异常，进程被终止。延后创建、加 `DontDestroyOnLoad` 均无法规避。

**结论与对策**：本作（Unity 2020.3.49 / IL2CPP 27.1 / Il2CppInterop 1.5.x）**放弃注入 MonoBehaviour**，改用：

```csharp
// 帧泵：补丁游戏自身的每帧方法（CursorController 常驻且每帧 Update）
AccessTools.Method(typeof(Wolfpack.CursorControl.CursorController), "Update")
→ Prefix: ModLoader.Tick()   // 用 Time.frameCount 去重，保证每帧只 tick 一次
```

该方案已实测稳定运行 55 秒 + 场景切换，无异常。

**连带影响**：IMGUI（`OnGUI`）依赖 MonoBehaviour 回调，随之不可用。因此 `IMod.OnGUI` 已从 API 移除，
**HUD 类 Mod 需改走 uGUI（Canvas + TextMeshPro）**，这是 P3 的工作项。

## 4. 过程中修复的问题

| 问题 | 修复 |
|---|---|
| `manifest.network: "client-only"` 无法反序列化为枚举 | 改为字符串 + `NetworkMode` 计算属性，容忍大小写与连字符 |
| `ModContext.Directory` 属性遮蔽 `System.IO.Directory` | 显式写 `System.IO.Directory.CreateDirectory` |
| 插件引用 Interop 程序集编译报 `CS0012` | csproj 增加 `Il2CppInterop.Runtime/Common`、`UnityEngine.InputLegacyModule` 等引用 |
| `GUI.Window` 委托编组失败 | 该 API 已随 IMGUI 一起移除；若需 UI 用 uGUI |

## 5. 对 P3 的影响

已完成（可直接作为地基）：清单与加载、依赖排序、逐帧泵、场景事件、运行时贴图、异常隔离、日志。

4. **网络桥**：复用 `W_NetworkManager` 的 `protocolChannel` 做 Mod 消息分帧与清单握手。
5. **Mods 菜单**：在 `W_SettingsMenu` 注入入口，展示已加载 Mod 与隔离状态。
